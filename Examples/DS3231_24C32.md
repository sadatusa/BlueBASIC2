# ZS-042 (DS3231 RTC + 24C32 EEPROM) BlueBASIC Hardware Guide

**Target Hardware:** Texas Instruments CC2541 BLE SoC (HM-10 Module)  
**Module Tested:** ZS-042 Real-Time Clock & EEPROM Module  
**Environment:** BlueBASIC Interpreter v1.4.0  
**Interface:** Software Bit-Bang I2C Master via compiled `WIRE` micro-engine  

---

## 1. Hardware Overview & Wiring

The **ZS-042** is an integrated I2C peripheral board featuring two independent slave devices sharing a common I2C bus:
1. **Dallas / Maxim DS3231:** Ultra-accurate, temperature-compensated Real-Time Clock (RTC) with integrated TCXO and internal die temperature sensor.
2. **HK24C32 / AT24C32:** 32-Kilobit (4,096-byte) serial I2C EEPROM.
3. **On-Board Pull-Up Resistors:** Integrated 4.7 kΩ pull-up resistors on both SCL and SDA lines to VCC.

### Wiring Diagram to CC2541 / HM-10

| ZS-042 Pin | Signal | CC2541 Chip Pin | HM-10 Pad / Label | Description |
| :--- | :--- | :--- | :--- | :--- |
| **VCC** | Power | VDD (2.0V – 3.6V) | Pin 12 (`VCC`) | Connect to 3.3V power supply |
| **GND** | Ground | GND | Pin 13 / 14 (`GND`) | Common ground |
| **SCL** | I2C Clock | `P0_4` (Pin 2) | Pad 30 (`PIO7`) | Default SCL clock line |
| **SDA** | I2C Data | `P0_5` (Pin 3) | Pad 29 (`PIO6`) | Default SDA data line |
| **SQW** | Square Wave / Int | Optional GPIO | Optional | 1 Hz / 32 kHz / Alarm output |
| **32K** | 32.768 kHz Output | Optional GPIO | Optional | Direct 32 kHz oscillator out |

> [!TIP]
> **Arbitrary Pin Selectability:** BlueBASIC uses a software bit-banged I2C engine (`I2C MASTER <scl> <sda> [PULLUP]`). If your CC2541 breakout uses other pins (e.g. `P1(2)` and `P1(3)` or `P1(3)` and `P0(5)`), simply change the pin arguments in line 50.

## 2. I2C Addressing & The 8-Bit Wire Rule

> [!IMPORTANT]
> **BlueBASIC requires the 8-bit wire address, NOT the 7-bit unshifted address!**  
> The BlueBASIC interpreter transmits the address byte directly onto the wire and inserts the Read/Write direction bit into bit 0 (`d |= rnw`).  
> Formula: $\text{BlueBASIC Address} = \text{7-Bit Device Address} \ll 1 \quad (\text{or } \text{7-Bit Address} \times 2)$

### Device Address Calculations

| Device | Configuration | 7-Bit Hex | 7-Bit Dec | BlueBASIC 8-Bit Hex (`<< 1`) | BlueBASIC Decimal |
| :--- | :--- | :--- | :--- | :--- | :--- |
| **DS3231 RTC** | Factory Fixed | `0x68` | 104 | `0XD0` | **`208`** |
| **24C32 EEPROM** | **A0, A1, A2 Open (Default Pullup)** | **`0x57`** | **87** | **`0XAE`** | **`174`** |
| 24C32 EEPROM | A0 Solder-Bridged to GND | `0x56` | 86 | `0XAC` | `172` |
| 24C32 EEPROM | A1 Solder-Bridged to GND | `0x55` | 85 | `0XAA` | `170` |
| 24C32 EEPROM | A0, A1 Bridged to GND | `0x54` | 84 | `0XA8` | `168` |
| 24C32 EEPROM | A2 Solder-Bridged to GND | `0x53` | 83 | `0XA6` | `166` |
| 24C32 EEPROM | A0, A2 Bridged to GND | `0x52` | 82 | `0XA4` | `164` |
| 24C32 EEPROM | A1, A2 Bridged to GND | `0x51` | 81 | `0XA2` | `162` |
| 24C32 EEPROM | A0, A1, A2 All Bridged to GND | `0x50` | 80 | `0XA0` | `160` |

## 3. Register Maps & Protocol Mechanics

### 3.1 DS3231 Real-Time Clock
Data bytes in registers `0x00` through `0x06` are stored in **Binary Coded Decimal (BCD)** format:

| Reg Addr | Name | Bit Range | Format / Conversion |
| :--- | :--- | :--- | :--- |
| `0x00` (0) | Seconds | `00–59` | `S = (((D(0) & 127) >> 4) * 10) + (D(0) & 15)` |
| `0x01` (1) | Minutes | `00–59` | `M = ((D(1) >> 4) * 10) + (D(1) & 15)` |
| `0x02` (2) | Hours | `00–23` (24h) | `H = (((D(2) & 63) >> 4) * 10) + (D(2) & 15)` |
| `0x03` (3) | Day of Week | `1–7` | `1 = Sunday, 2 = Monday, ...` |
| `0x04` (4) | Date | `01–31` | `D = ((D(4) >> 4) * 10) + (D(4) & 15)` |
| `0x05` (5) | Month / Century | `01–12` | `MO = (((D(5) & 31) >> 4) * 10) + (D(5) & 15)` |
| `0x06` (6) | Year | `00–99` | `Y = ((D(6) >> 4) * 10) + (D(6) & 15)` |
| `0x11` (17)| Temp MSB | Signed integer | `C = T(0)` (Degrees Celsius) |
| `0x12` (18)| Temp LSB | Bits 7:6 | `F = (T(1) >> 6) * 25` (Hundredths of °C: `.00`, `.25`, `.50`, `.75`) |

### 3.2 HK24C32 16-Bit Word Addressing
Unlike 256-byte EEPROMs (such as the 24C02) which take a single 8-bit memory offset, the 24C32 has **4,096 bytes** ($0x0000$ to $0x0FFF$). It requires a **two-byte word address**:
- **Write Syntax:** `I2C WRITE <addr_8bit>, <addr_hi>, <addr_lo>, <byte1>, <byte2>, ...`
- **Read Syntax:** `I2C WRITE <addr_8bit>, <addr_hi>, <addr_lo>, READ <array>`
- **Internal Write Time ($t_{\text{WR}}$):** Following any write command, the EEPROM initiates an internal self-timed page programming cycle taking up to **5 ms**. A mandatory `DELAY 10` must precede any subsequent read or write.

## 4. Complete Hardware-Tested BlueBASIC Program

The following program has been uploaded, validated, and executed on CC2541 hardware over serial:

```basic
10 REM ========================================================
20 REM ZS-042 MODULE INTERFACE: DS3231 RTC + HK24C32 EEPROM
30 REM ========================================================
40 REM CONFIGURE SCL AND SDA (CHANGE PINS TO MATCH YOUR WIRING)
50 I2C MASTER P0(4) P0(5) PULLUP
60 PRINT "========================================"
70 PRINT "ZS-042 HARDWARE TEST: DS3231 + 24C32"
80 PRINT "========================================"
90 REM --------------------------------------------------------
100 REM 1. READ TIME FROM DS3231 (ADDRESS 208 = 0XD0)
110 REM --------------------------------------------------------
120 DIM D(7)
130 I2C WRITE 208, 0, READ D
140 S = (((D(0) & 127) >> 4) * 10) + (D(0) & 15)
150 M = ((D(1) >> 4) * 10) + (D(1) & 15)
160 H = (((D(2) & 63) >> 4) * 10) + (D(2) & 15)
170 PRINT "CURRENT TIME:  ", H, ":", M, ":", S
180 REM READ ON-BOARD TEMPERATURE SENSOR (REGISTERS 17 & 18)
190 DIM T(2)
200 I2C WRITE 208, 17, READ T
210 C = T(0)
220 F = (T(1) >> 6) * 25
230 PRINT "DIE TEMP:      ", C, ".", F, " C"
240 REM --------------------------------------------------------
250 REM 2. TEST HK24C32 EEPROM (ADDRESS 174 = 0XAE)
260 REM --------------------------------------------------------
270 PRINT "--- EEPROM 16-BIT WORD ADDRESS TEST ---"
280 PRINT "WRITING TEST BYTES TO EEPROM ADDR 0X0020..."
290 REM 16-BIT ADDRESS: HIGH=0, LOW=32 (0X0020), DATA: 65, 66 ('A', 'B')
300 I2C WRITE 174, 0, 32, 65, 66
310 REM WAIT 10 MS FOR INTERNAL WRITE CYCLE (tWR)
320 DELAY 10
330 DIM R(2)
340 I2C WRITE 174, 0, 32, READ R
350 PRINT "EEPROM READ:   ", R(0), " ", R(1)
360 X = (R(0) == 65)
370 Y = (R(1) == 66)
380 IF X & Y
385 PRINT "VERIFICATION:  PASSED (DATA MATCH)!"
390 ELSE
395 PRINT "VERIFICATION:  FAILED!"
400 END
410 PRINT "========================================"
420 RETURN
```

## 6. Critical BlueBASIC Implementation Rules & Gotchas

Through hardware execution testing on the CC2541, four crucial interpreter architectural constraints were identified:

### 1. Direct Mode vs. Program Mode Execution
- **The Issue:** Typing `I2C WRITE 208, 0, READ D` directly at the interactive terminal prompt results in `Bad expression`.
- **The Cause:** BlueBASIC's interactive command buffer resides at `heap + sizeof(LINENUM)`. When executing I2C commands, the interpreter dynamically compiles `WIRE` bytecode starting at `heap`. In direct mode, writing the bytecode directly clobbers the active line being parsed!
- **The Solution:** I2C read and write commands **must be stored in numbered program lines** (which reside safely in flash memory) and executed via `RUN`.

### 2. Expression Evaluation Queue Limit (`EXPRESSION_QUEUE_SIZE 8`)
- **The Issue:** A compound condition like `IF R(0) == 65 AND R(1) == 66 AND R(2) == 67 AND R(3) == 68 THEN PRINT ...` aborts with `Out of memory`.
- **The Cause:** Line 548 of `BlueBasic_Interpreter.c` defines `#define EXPRESSION_QUEUE_SIZE 8`. An expression with multiple chained comparisons and boolean operators exceeds the fixed 8-element stack.
- **The Solution:** Break multi-byte comparisons into staged evaluations:
  ```basic
  240 X = (R(0) == 65)
  250 Y = (R(1) == 66)
  260 IF X & Y
  270 PRINT "MATCH!"
  280 END
  ```

### 3. No `THEN` Keyword (Structured `IF ... ELSE ... END`)
- Unlike traditional BASIC, BlueBASIC does **not** support the `THEN` keyword (`THEN` produces `Bad expression`).
- Conditionals must be structured as multi-line blocks terminated with `END`:
  ```basic
  IF <condition>
    <statements>
  ELSE
    <statements>
  END
  ```

### 4. Variable Naming
- BlueBASIC strictly supports **single-letter variable names** (`A` through `Z`). Names like `SEC`, `TEMP`, or `ADDR` produce syntax errors (`Error` or `Bad expression`).

### 5. Serial Pacing When Uploading Code
- When sending program lines to the BlueBASIC terminal over UART at 9600 baud, send characters with a **5 ms inter-character delay** and lines with an **80–100 ms delay** to prevent buffer overruns during flash sector writes.

## 7. CC2541 Hardware I2C (`HWI2C`) Real Hardware Validation

### 7.1 Hardware I2C Wiring
The ZS-042 module was connected directly to the dedicated hardware I2C pins of the CC2541:
- **VCC:** 3.3V
- **GND:** GND
- **SCL:** CC2541 **Pin 2** (Dedicated Hardware SCL)
- **SDA:** CC2541 **Pin 3** (Dedicated Hardware SDA)

### 7.2 CC2540 vs. CC2541 Compatibility
- **CC2541 (`CHIPID == 0x41`):** Hardware I2C fully supported on pins 2 and 3.
- **CC2540 (`CHIPID == 0x8D`):** Hardware I2C is not available. Executing `HWI2C` commands cleanly raises the error:
  ```text
  HWI2C not Available
  ```

### 7.3 Direct Mode Support
Unlike Software I2C (`I2C`), which compiles bytecode onto the heap and requires numbered program lines, `HWI2C` operates directly via hardware registers (`I2CCFG`, `I2CDATA`, `I2CSTAT`), enabling **both direct interactive execution and program execution**.

### 7.4 Verified Hardware Program

```basic
10 REM ========================================================
20 REM CC2541 HARDWARE I2C (HWI2C) REAL TEST WITH ZS-042
30 REM ========================================================
40 HWI2C MASTER 100
50 PRINT "========================================"
60 PRINT "CC2541 HARDWARE I2C REAL TEST: DS3231 + 24C32"
70 PRINT "========================================"
80 REM 1. READ TIME FROM DS3231 (ADDRESS 208 = 0XD0)
90 DIM D(7)
100 HWI2C WRITE 208, 0, READ D
110 S = (((D(0) & 127) >> 4) * 10) + (D(0) & 15)
120 M = ((D(1) >> 4) * 10) + (D(1) & 15)
130 H = (((D(2) & 63) >> 4) * 10) + (D(2) & 15)
140 PRINT "CURRENT TIME:  ", H, ":", M, ":", S
150 REM 2. READ DIE TEMPERATURE
160 DIM T(2)
170 HWI2C WRITE 208, 17, READ T
180 C = T(0)
190 F = (T(1) >> 6) * 25
200 PRINT "DIE TEMP:      ", C, ".", F, " C"
210 REM 3. WRITE AND READ HK24C32 EEPROM
220 PRINT "--- EEPROM 16-BIT WORD ADDRESS TEST ---"
230 HWI2C WRITE 174, 0, 64, 72, 73, 74
240 FOR I = 1 TO 400
245 NEXT I
250 DIM E(3)
260 HWI2C WRITE 174, 0, 64, READ E
270 PRINT "EEPROM READ:   ", E(0), " ", E(1), " ", E(2)
280 X = (E(0) == 72)
290 Y = (E(1) == 73)
300 Z = (E(2) == 74)
310 IF X & Y & Z
320 PRINT "VERIFICATION:  PASSED (ALL BYTES MATCH)!"
330 ELSE
340 PRINT "VERIFICATION:  FAILED!"
350 END
360 PRINT "========================================"
370 RETURN
```
